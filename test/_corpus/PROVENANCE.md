# Vendored test corpus — provenance

The fixtures under `test/_corpus/` are copies of upstream ICU4X test
fixtures + Unicode UCD source files. Tests use them to verify the
icu_kit Dart facade against the same data the upstream Rust + canonical
Unicode authorities use.

### `ucd/auxiliary/` — segmenter break tests

These come from upstream ICU4X's `tests/testdata/`, NOT direct from
unicode.org. ICU4X tailors these fixtures to match its own segmenter
implementation:

- `LineBreakTest.txt` is **upstream-tailored** (header: "THIS IS NOT
  LineBreakTest-15.1.0.txt"). Generated from UCD 15.1 with LB25
  tailoring removed via the unicodetools `15.1-no-lb-tailoring` branch.
  Unicode 16.0+ is supposed to produce equivalent output natively, but
  ICU4X 2.2 still uses the tailored fixture.
- `GraphemeBreakTest.txt`, `WordBreakTest.txt`, `SentenceBreakTest.txt`
  are vendored UCD 17.0 unchanged from unicode.org.

We use upstream's modified versions (not unicode.org direct) so our
corpus tests verify what ICU4X CLAIMS to do, not the official UAX #14 /
UAX #29 semantics ICU4X chooses to depart from.

| Local path | Upstream path |
|---|---|
| `ucd/auxiliary/{Grapheme,Word,Sentence,Line}BreakTest.txt` | `vendor/icu4x/components/segmenter/tests/testdata/{Grapheme,Word,Sentence,Line}BreakTest.txt` |

The Unicode version of our corpus MUST match the Unicode version of the
data baked into our pinned ICU4X submodule. ICU4X 2.2's
`provider/data/properties` is generated from Unicode 17.0; corpus rows
that disagree with what ICU4X returns indicate either (1) corpus drift
(refresh the UCD copy) or (2) a real binding bug.

IDNA test fixture is Unicode 16.0 (latest available as of 2025-11) —
matches the upstream Rust idna crate's own conformance fixture version.

### `postcards/` — generated ICU4X data blobs

Unlike the other fixtures (which are upstream test data we copy as-is),
the postcard fixtures are **generated by us** using the upstream
`icu4x-datagen` Rust binary against the vendored `vendor/icu4x` source.
Each `.postcard` file is a binary blob holding a curated set of ICU4X
data markers for one locale, used by the IcuData / IcuDataSource / lazy
data loading round-trip tests.

| Local path | Locale | What it covers |
|---|---|---|
| `postcards/en_minimal.postcard` | en | Plurals + decimal + datetime + locale fallback |
| `postcards/fr_minimal.postcard` | fr | Same markers, French data |
| `postcards/ja_minimal.postcard` | ja | Same markers, Japanese data |

The exact marker list is in `tool/regen_test_postcards.dart`. To
regenerate (e.g. after bumping the ICU4X submodule):

```bash
fvm dart run tool/regen_test_postcards.dart
```

The fixtures change byte-for-byte across ICU4X bumps. Commit them
together with the submodule bump.

## Updating the corpus

See `docs/UPDATING.md` for the full procedure.

Short version:

1. Upgrade the `vendor/icu4x` submodule to a newer ICU4X tag.
2. Find the Unicode version of the new ICU4X's properties data:
   `cat vendor/icu4x/provider/data/properties/Cargo.toml | grep icuexport`
   then look up which Unicode version that ICU release ships.
3. Re-fetch the matching UCD files into `ucd/`.
4. Re-copy the JSON fixtures from the new ICU4X tag's
   `components/*/tests/fixtures/`.
5. Regenerate the postcard fixtures with the new submodule version:
   `fvm dart run tool/regen_test_postcards.dart`
6. Re-run the corpus tests. New failures are real divergences — fix
   the binding or file the upstream issue.
7. Bump this file's "Unicode version" + "Vendored on" + "Source tag".

## Why we vendor as plain copies (not a git submodule of UCD)

Same reasoning as fluent_kit's corpus: a few MB of read-only test data.
Submodule indirection costs more than it saves at this scale. This
file is the manual ledger.

## What's NOT vendored

- ICU4X's compiled Rust source — we link against the submodule directly.
- ICU4X's collation / segmenter LSTM / casemap test fixtures stored as
  Rust constants — those are extracted at corpus-update time if a
  Dart-compatible JSON form is wanted. Currently not vendored; would
  require a Rust-side dump tool. Tracked in CAPABILITY_ROADMAP.md.
